# 88 版：设备保存历史，手机按需查看

适用分支：`codex/battery-88-csv`；构建配置：`gauge88-csv`。私用 APK 沿用 `cn.mu5120.console` 包名和已有签名，公共版本号仍为 `1.3.58` / `78`。

## 连接与查看

手机连接设备所在局域网，在「设置 → 路由器连接」填写管理地址和电池地址。默认从 `http://192.168.0.1:88/backup/battery-log.csv` 读取历史。设备保存日志，历史读取无需先成功登录原厂管理接口。

启动、回到应用及手动刷新时读取历史；前台每分钟更新一次。可查看最近 2 小时或 24 小时，窗口以最后一条设备记录为终点。App 关闭、手机息屏期间保存的记录，会在再次打开时从设备补齐。

## 曲线与字段

| 内容 | 设备 CSV 字段 |
| --- | --- |
| 下载与上传 | `download_bps`、`upload_bps`，单位 B/s，结合 `net_interval_s` 检查有效采样 |
| 电量与电池温度 | `soc`、`temp_c`；充放电来自 `status`，外部供电来自 `usb_online` |
| CPU、Modem、PA 温度 | `cpu_temp_c`、`modem_temp_c`、`pa_temp_c` |
| LTE 信号 | `lte_rsrp_dbm`、`lte_rsrq_db`、`lte_snr_db` |
| NR 信号 | `nr_rsrp_dbm`、`nr_rsrq_db`、`nr_sinr_db` |
| 记录时间与制式 | `ts_iso`、`ts`、`network_type` |

LTE 和 NR 分别显示；缺失值保持为空，实际零值保留。旧 8/12 列日志不补造新增指标。无效时间、时间倒退、采样缺口及网络制式变化处保留断点，避免把不连续记录连成正常曲线。

时间按设备日志的无时区日历文本显示。设备原始 `ts` 已实测约比真实 UTC 快 8 小时，不能直接当作手机 Unix 时间显示。历史刷新失败时保留已读到的当前设备历史，并显示错误和最后记录时间；更换电池地址后不混入上一设备的缓存。

## 手机后台与悬浮窗

关闭悬浮窗时，手机不为曲线运行常驻采集、定时唤醒或唤醒锁，开机和覆盖更新也不会恢复旧采集服务。开启悬浮窗时，服务仅显示现有实时网速、电量与温度；息屏暂停查询，不归档曲线或在后台轮询短信。

旧手机历史文件保留，但不再读取、合并或继续写入设备曲线。当前实时首页、设备列表、短信、套餐、网络调优和控制仍使用原有接口。续航估算继续使用设备 CSV 的原有算法，放电估算到 0%。

## 安装

使用本分支构建的私用 88 APK 覆盖安装，保留应用数据。卸载或清除应用数据会删除手机配置。公共 GitHub Release 的下载链接对应常规版；本次设备历史改动仅保存在 88 分支及私用安装包中。

验证记录见 [设备历史验证](verification-device-chart-history-2026-11-18.md)。
