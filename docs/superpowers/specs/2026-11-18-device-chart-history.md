# 88 版折线图改用设备历史

用户已明确：替换 App 保存采样 JSON、供折线图使用的功能；不是替换当前实时 dashboard 和管理接口。仅在 `codex/battery-88-csv` 实现，不同步常规分支，不修改或部署设备端服务。

## 行为

- 网速、温度、LTE/NR 信号、电量曲线及电池历史列表直接读取 `http://<电池地址>:88/backup/battery-log.csv`。设备持续记录，因此 App 关闭/手机息屏期间的历史无需手机采集。
- 每分钟更新设备历史，启动、回到页面、手动刷新时读取；请求合并、缓存、端点变更与失败不得混入上一设备数据。读取失败可保留当前设备已读取历史，但明确失败及截至时间。
- 原厂实时 dashboard、短信、设备列表、套餐、网络调优和控制保持当前行为。历史 CSV 读取独立于原厂登录成功与否。
- 设备 CSV 25 列包括电池/USB、B/s 网速、CPU/Modem/PA 温度、网络制式、LTE/NR 信号。空值表示缺失，零值保留。旧8/12列记录不补造新增指标。保留不同LTE/NR曲线及制式/缺口边界。
- 图表按最后设备记录确定2/24小时窗口，显示设备记录的无时区墙钟文本。已实测设备 `ts` 比真实UTC大约8小时，不能直接作为手机Unix毫秒；使用严格校验的 `ts_iso` 显示时间，同时保留原始ts作为样例身份。逆序/无效记录不得连成正常连续曲线。
- 88版不读取或合并旧手机图表/电池采样文件，不继续生成曲线JSON，不将设备历史标成前台/后台采集。允许保留短期内存缓存；旧文件不破坏性删除。
- 88版悬浮窗关闭时没有后台轮询、唤醒锁、定时唤醒或重启恢复服务；开启悬浮窗时仅为悬浮实时显示运行，不归档曲线或后台轮询短信；息屏不继续查询。常规配置下现有行为通过回归保护。
- 后台权限/诊断文案明确设备保存历史，手机无需常驻采集；电池续航仍使用原有设备CSV估算到0%的口径。

## 验证

覆盖CSV25列及旧列、空值/零值/异常/倒退/缺口、时钟偏差、设备更换、CSV失败与恢复、关闭App后完整历史、只读历史不需要原厂登录、旧缓存不混入、悬浮开关与息屏策略、常规模式回归。执行JS与JVM测试、APK构建与签名/profile检查；手机可用时覆盖安装私用88包保留数据，实测曲线和关闭悬浮窗后的服务状态。公共Release及常规分支保持不变。
