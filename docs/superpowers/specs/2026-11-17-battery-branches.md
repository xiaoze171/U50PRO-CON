# Battery source branches

User approved on 2026-11-17: the existing `codex/daily-monitor-ui` branch keeps factory battery collection and its original runtime calculation, and a new `codex/battery-88-csv` branch uses the port 88 battery service. Both use the current UI source, with no duplicated pages/components.

One tracked `config/battery-profile.json` selects `factory` or `gauge88-csv`. Both branches contain the same implementation; their final source difference is this configuration. JavaScript imports it; Gradle generates the matching native BuildConfig field. Saved settings cannot override a branch's source; the gauge port is fixed at 88, and optional battery host still follows the router by default. Settings present the effective source using the shared UI.

Factory collection reads factory percentage, charge flags, temperature and legacy battery details. Its estimate follows the existing HEAD algorithm: most recent continuous same-charge segment within 24 hours, at least 0.15 hours, positive SOC change, endpoint slope to 0% or 100%. Adapt its output to the shared UI time objects. Filter out gauge history. Preserve legacy external-power charge semantics for this profile.

Gauge collection reads `/state.json`, and runtime/charge speed analysis reads `/backup/battery-log.csv` on the same port 88 host. CSV never silently falls back to app-collected samples. CSV is cached for 60 seconds per endpoint with request coalescing, bounded input, timeout/error state and invalidation when the endpoint changes. Do not send or absorb factory session cookies for either gauge route. Polls that started before configuration changes cannot publish results afterward.

CSV parsing supports BOM, CRLF, quoted fields, named/reordered columns, old eight-column records with the extended header, and missing USB columns. Required fields: ts, soc, voltage_mv, current_ma, power_w, temp_c, status (ts_iso is display only). Invalid records are segment boundaries, not silently removed bridges. Unknown headers may be ignored; duplicate or missing required headers fail. Limit to 4 MiB / 50000 records.

Analysis uses the latest continuous matching charge/discharge segment, rejects non-positive intervals or gaps above 120 seconds and SOC corrections/direction conflicts, and uses at most the last two hours. Require at least one hour and 31 points with 0.2 percentage point movement and 0.05 Wh energy. Compute SOC slope using duration and actual SOC movement; current live SOC determines time to 0% (discharge) or 100% (charge). Check the last CSV record against state.json device ts (age 0..120 seconds), separately from the freshness of the live marker. Never compare the device clock directly to the phone clock. Check the join from the last CSV row to live SOC/current/mode for correction and discontinuity. Break on reboot where boot uptime identifies the boundary. No invented CSV boot/capacity identity. Reuse existing full/confirming/tapering/low-voltage guards. Missing/stale/failed CSV yields explicit unavailable/collecting state with no number.

Native background and foreground implement equivalent behavior; LAN viewers retain collector calculations. Share deterministic CSV fixtures between JavaScript and native tests. Keep existing local monitoring history distinct from device CSV analysis; no bulk import into app history. Include CSV analysis provenance/status in compact battery summaries so shared UI can explain failures.

Validate the existing tests, new parser/model/cache/profile and native cases, H5 builds for both profiles, native compilation, and exact UI source identity across branch tips. Preserve pre-existing untracked packages/tools. No push or device installation requested.
