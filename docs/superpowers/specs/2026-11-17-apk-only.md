# APK-only application

User approved removal of EXE functionality and all LAN interoperability, including phone-to-phone synchronization, discovery and collector election, on 2026-11-17.

The application retains Android APK functionality: router monitoring/control, SMS, battery statistics, charts/history, local foreground/background recovery, overlay, embedded stock router UI, and APK updates. Android remains the only shipped runtime. The uni/Vue/H5 build and development preview are retained because Gradle embeds the generated H5 application in the APK.

Remove tracked Electron desktop sources/dependencies/package files, EXE build/start scripts, DesktopRouter bridge fallback, LAN UI/state/lifecycle, peer transport/history imports, election, native sync HTTP/UDP services and bridge methods, and discovery-only multicast permission. Remove tests that exclusively exercise deleted products/protocols. Existing untracked installers/tools are preserved.

Preserve local history normalization and merging used when Android foreground recovers native background archives. Rename misleading external/peer APIs to local/background names and retain acquisition timestamps, battery summaries, measurement provenance, source tags, validation and ownership resets. Do not disable local collection because a previously saved sync preference was enabled.

Native cleanup must retain router authentication hashing, request/history executor shutdown, same-phone session handoff, background service/Wi-Fi lock, overlay, and the localhost stock-router proxy. Extract SHA256 from the deleted SyncServer dependency with identical UTF-8 input and uppercase hexadecimal output. Only CHANGE_WIFI_MULTICAST_STATE is removed from the manifest for this scope.

The browser battery development proxy must not import deleted desktop modules. It only needs the existing private/local-host validator; keep proxy routes, cookie isolation and bounds. Keep transitive browser compatibility dependencies such as electron-to-chromium; they are not Electron application functionality.

Both battery branches continue using identical source and UI, differing only in config/battery-profile.json: codex/daily-monitor-ui uses factory and codex/battery-88-csv uses gauge88-csv. Their calculation behavior is preserved.
