## 当前问题与证据

1. **首页缺少日常摘要。** `src/pages/index/index.vue:63` 先展示制式、RSRP/SINR/CA、速度，再放温度大图和设备标识；电量、流量、连接设备数量分散在其他页。
2. **手机缺少持续可见的数据状态。** `index.css:2129` 隐藏侧栏连接卡，`:2330` 隐藏来源与更新时间。错误横幅仍存在，但实时、离线缓存和更新时间的辨识不足。
3. **视觉权重过于平均。** 大面积四色渐变、玻璃模糊、高光、阴影、卡片套卡片，让专业参数和主要指标争夺注意力。历史截图可支持这个判断；截图中的空白曲线不能据此认定当前版本存在绘图故障。
4. **管理页不符合常用顺序。** 默认进入短信，发送表单在收件箱之前；设置先显示软件更新，再显示连接配置。四个管理子入口仍使用三列 CSS。
5. **部分界面语言偏向内部实现。** 动态 LD、SHA-256、代理方式、记录样本数适合放入诊断详情。用户关心的采集情境仍应方便查看。
6. **存在独立的数据表达问题。** 手动选择较弱邻区后标题仍称“最强”；`formatHours(12.999)` 离线实测输出“12小时 60分钟”；充电状态缺失时被默认解释为电池供电。

## Wi-Fi 芯片温度 -80

已确认的是应用未校验温度有效性，而不是已经确认某个固件错误码：

- `src/services/router-fields.json:18` 请求 `wifi_chip_temp`；`router-client.js:469` 将温度响应原样交给页面。
- `src/pages/index/index.vue:864` 只检查非空并追加 `°C`；输入 `"-80"` 会显示 `-80°C`，没有单位换算。
- `index.vue:1188` 仅做数值解析后归档。离线执行页面真实函数确认：该值可进入采集、持久化、回读、跨端合并和图表数据。
- 平滑还会放大影响：同来源 `[40, -80, 40]` 会得到 `[-20, 0, -20]`。
- Android `MonitorHistoryStore.java:122` 同样只有有限数字和字段名判断；这一点为静态审查，未执行真机验证。
- 聊天记录没有提供该设备 `-80` 的官方语义或换算依据，不能擅自改成 `80`、`0` 或其他温度。
- 用户补充的刷入时间关系，使刷入内容与温度字段的兼容性成为优先排查方向，但不足以确定 `9461` 的具体包类型或断言其一定导致该读数。
- 另有独立兼容性疑点：项目已请求 `wifi_temp_level_1`、`wifi_temp_level_2`，接口清单将它们列为 Wi-Fi 温度传感器；当前页面和原生历史却按名称包含 `level` 一律排除。需要核对当前设备这两个字段的实际响应，若有效则按各自传感器名称展示，不能未经核实替代为同一个“Wi-Fi 芯片”测量值。`therm_*_level` 热保护等级仍不能当成摄氏温度。

建议：温度使用专门的数据校验规则；疑似无效值以“— / 读数异常”呈现，在诊断详情保留原始字段和值，不参与正常温度图表或统计。处理范围覆盖实时入口、已有历史回读、同步合并和原生后台。不能在通用 `numeric()` 中禁止负数，因为信号指标的负值可能有效。设备的具体无效值规则须结合原始返回和固件证据确定。

## 建议的第一版结构（待确认）

比较三种方案：沿用现有五页仅调整样式成本较低，但日常信息仍分散；自定义仪表盘灵活，但增加配置负担。推荐固定的日常监控首页，并将详细记录和设备操作分开。

| 一级入口 | 默认内容 | 二级内容 |
| --- | --- | --- |
| 首页 | 持续可见的连接/更新时间、实时上下行、本月流量、电量与充放电、关键温度 | 点击对应指标进入详情；连接设备和未读短信快捷入口 |
| 趋势 | 网速、温度、电池、信号的指标切换 | 2 小时/24 小时范围、详细记录与来源；少量可读时间刻度，不恢复拖动滑块 |
| 设备 | 已连接客户端、网络概况、当前锁定摘要 | 网络调优（邻区、锁小区、LTE/SA/NSA 锁频）、短信、原厂后台、设备详情和控制 |
| 设置 | 路由器连接、后台监控与悬浮窗、局域网互通 | 更新、采集诊断、关于 |

首页布局自上而下：

1. 设备名、连接状态、简短网络信息与最近更新时间。
2. 大号实时下载/上传数字，配紧凑速率趋势。
3. 电池、本月流量、关键温度摘要。未配置套餐时显示已用量，不假造剩余额度；续航明确标为估算。
4. 连接设备、短信快捷入口。温度异常通过对应指标表达，详细原始数据可点开查看。

视觉方向：浅灰页面、清晰白色内容区、深灰正文、蓝色强调，缩小卡片嵌套和装饰。颜色同时配文字表达状态。手机保持清楚的点击区域；桌面采用侧栏和多列摘要，利用宽度并排查看趋势与设备信息。

首版优先改善已有能力，不预设新增云端远程管理、AI 诊断、自动锁频、测速服务或自定义仪表盘。这些都需要额外需求和接口依据。

## 实施与验证边界
